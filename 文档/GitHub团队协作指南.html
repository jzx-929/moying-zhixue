1GitHub 是什么？为什么用它？

一句话说明：GitHub 是一个代码托管平台，就像"代码版的百度网盘 + 团队协作工具"。

对我们项目的价值

  • 代码同步 每个人写的代码都在一个地方，不用到处发压缩包
  • 版本记录 每次修改都有记录，随时可以回退到之前的状态
  • 协作开发 多人同时开发不同功能，最后合并到一起
  • 代码审查 提交代码前需要别人检查，减少 Bug
新生提示：不用怕，日常开发只需要记住 5 个命令（后面会讲）。把它当成"保存 + 同步"的工具就行。

2环境准备（第一次使用）

步骤 1：安装 Git

下载地址：https://git-scm.com/downloads

选择 Windows 版本，一路"下一步"安装即可。安装完成后，桌面右键应该能看到 Open Git Bash Here 选项。

步骤 2：注册 GitHub 账号

访问 https://github.com/signup 注册账号，注册完成后把用户名发给组长，邀请你加入仓库。

步骤 3：配置身份信息

打开 Git Bash（或 PowerShell），运行以下命令（只需一次）：

git config --global user.name "你的名字" git config --global user.email "你的邮箱@xx.com"
注意：邮箱要和 GitHub 注册邮箱一致，这样你的提交才能正确关联到 GitHub 头像。

步骤 4：接受仓库邀请

组长邀请后，你会收到一封邮件，点击邮件中的链接接受邀请。也可以直接访问仓库页面：https://github.com/jzx-929/moying-zhixue

3获取仓库代码

接受邀请后，把项目代码下载到本地（只需第一次执行）：

# 进入你想存放项目的文件夹 cd D:/桌面/竞赛 # 克隆仓库（复制一份到本地） git clone https://github.com/jzx-929/moying-zhixue.git # 进入项目目录 cd moying-zhixue

克隆完成后，你的本地就有了完整的项目文件，和 GitHub 上的一模一样。

4日常开发工作流（核心！）

每次写代码，遵循这个循环：

① 拉取最新代码
→
② 创建功能分支
→
③ 写代码
→
④ 提交
→
⑤ 推送
→
⑥ 发起 PR

对应的命令

# ① 拉取最新代码（每次开始工作前先执行） git checkout main git pull origin main # ② 创建你自己的功能分支（名字要有意义） git checkout -b feature/前端-文影创作坊 # ③ 写代码...（用你的编辑器/IDE 正常写） # ④ 把修改的文件加入暂存区并提交 git add . git commit -m "feat: 完成文影创作坊页面布局" # ⑤ 推送到 GitHub git push origin feature/前端-文影创作坊 # ⑥ 在 GitHub 网页上发起 Pull Request（后面详细讲）
5 个核心命令记忆口诀：pull → checkout -b → add → commit → push

5分支管理策略

我们采用简化的 Git Flow 模型，分支分三类：

分支类型 命名格式 用途 谁可以操作
main main 稳定版本，随时可演示 只通过 PR 合并，不直接提交
功能分支 feature/描述 开发新功能 每个人自己创建
修复分支 fix/描述 修复 Bug 每个人自己创建

命名示例

# ✅ 好的命名 feature/前端-文影创作坊 feature/AI-文改Agent feature/后端-FastAPI框架搭建 fix/登录页面样式错乱 # ❌ 不好的命名 feature/test my-branch update
红线：绝对不要直接往 main 分支提交代码！所有修改必须通过 Pull Request 合并。

6Pull Request 协作流程

当你完成一个功能并推送到 GitHub 后，需要发起 Pull Request（简称 PR）让别人检查代码后合并：

操作步骤

  1. 推送代码后，打开仓库页面 https://github.com/jzx-929/moying-zhixue
  2. 页面顶部会出现黄色横条提示 Compare & pull request，点击它
  3. 填写 PR 标题和描述：
    • 标题：简明说明做了什么，如 feat: 完成文影创作坊页面布局
    • 描述：列出改了哪些文件、实现了什么功能
  4. 点击 Create pull request
  5. 通知对应的组员或组长进行 Code Review（代码审查）
  6. 审查通过后，点击 Merge pull request 合并到 main

Commit 消息规范

前缀含义示例
feat新功能feat: 完成水墨动画生成接口
fix修复Bugfix: 修复OCR中文识别乱码
docs文档更新docs: 更新API接口文档
style样式调整style: 调整首页配色方案
refactor重构代码refactor: 重构Agent调用逻辑

7命令速查表

最常用（每天都要用）

git pull origin main # 拉取最新代码 git checkout -b feature/xxx # 创建并切换到新分支 git add . # 添加所有修改文件到暂存区 git commit -m "描述" # 提交到本地仓库 git push origin feature/xxx # 推送到远程仓库

查看状态

git status # 查看哪些文件被修改了 git log --oneline -5 # 查看最近5条提交记录 git branch # 查看当前在哪个分支 git diff # 查看具体改了什么内容

分支操作

git checkout main # 切换回 main 分支 git branch -a # 查看所有分支（含远程） git branch -d feature/xxx # 删除已合并的本地分支

撤销操作

git checkout -- 文件名 # 撤销某个文件的修改（还没add） git reset HEAD 文件名 # 撤销 add（还没commit） git reset --soft HEAD~1 # 撤销最近一次 commit（代码保留）

8常见问题与排错

Q1：push 时提示密码错误？

GitHub 已不支持密码登录，需要使用 Personal Access Token（PAT）：

  1. 访问 GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)
  2. 点击 Generate new token，勾选 repo 权限
  3. 生成后复制 token，push 时密码处粘贴这个 token

Q2：pull 时提示冲突怎么办？

# 1. 先看哪些文件冲突 git status # 2. 打开冲突文件，找到 <<<<<<< 标记的地方 # 手动选择保留哪段代码，删掉标记符号 # 3. 解决后重新提交 git add . git commit -m "resolve: 解决xxx冲突" git push origin 你的分支名

Q3：不小心提交了大文件怎么办？

联系组长处理，不要反复尝试 push。大文件（模型权重、视频等）不要提交到 Git，它们已在 .gitignore 中被忽略。

Q4：想撤销已经 push 的提交？

git revert HEAD # 创建一个反向提交来撤销 git push origin 你的分支名
警告：不要用 git push --force，除非你非常确定自己在做什么！

9团队协作规范

每日必做

  • 开始工作前：git pull origin main 拉取最新代码
  • 结束工作时：确保代码已 push 到自己的分支
  • 功能完成后：及时发起 PR，不要攒一大堆代码才提交

提交规范

  • 每次 commit 只做一件事，不要一个 commit 混合多个功能
  • commit 消息要写清楚做了什么，用中文或英文均可
  • 不要提交临时文件、调试日志、IDE 配置（已被 .gitignore 忽略）
  • 不要提交大文件（> 10MB），模型权重等放 MinIO 或网盘

PR 规范

  • PR 标题用 类型: 描述 格式
  • 描述中说明：改了什么、为什么改、怎么测试
  • 至少 1 人 Review 通过后才能合并
  • PR 合并后，删除已合并的功能分支，保持仓库整洁

各组对接重点

组别关注目录注意事项

AI模型组ai/模型权重不入库，只提交代码和配置

记住一句话：先 pull，再开发，小步提交，及时推送，发 PR 等审查。
